# Experiment #02 — Differential Analysis: Idle Lobby vs Settings Control

## 1. Overview
- **Baseline A (Idle Lobby):** 60 seconds passive capture while game stood motionless in main lobby.
- **Baseline B (Settings Control):** ~35 seconds capture during user action: Lobby -> Open Settings -> wait 5s -> Close Settings back to Lobby.

## 3. Findings

1. **Zero New Persistent Hosts Generated by Settings:**
   Opening and closing Settings did NOT spawn any new TCP connections, nor did it resolve any new domain names.
2. **Local UI Isolation:**
   Game settings UI interactions are rendered locally client-side; no settings-sync or settings-telemetry traffic was generated over the wire.
3. **RPC Traffic Bursts:**
   Opening and closing Settings generated small incremental packet bursts on the existing primary game channel (`43.129.146.99:17500`).
4. **Implication for Experiment #03:**
   Any NEW host, new port, or distinct burst that appears during Friend Search (UID 5421835339) can be definitively attributed to the social search action rather than basic UI rendering or background presence.
